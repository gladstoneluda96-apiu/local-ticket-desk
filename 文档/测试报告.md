## 3. 测试方法

1. **接口级**：直接对本地服务的 `/api/recognize`、`/api/ocr`、`/api/warmup`、`/api/tickets` 发送真实请求，测量耗时并校验返回结构。
2. **界面级**：用浏览器自动化真实操作页面（粘贴截图、点击创建、编辑字段、切换状态、收起抽屉、切换主题），断言 DOM 状态。
3. **视觉级**：截图后对按钮区域做像素采样，计算文字与背景的真实对比度。
4. **数据级**：直接查询 SQLite 校验落库结果，测试结束后清理测试数据。

测试全部使用真实素材：一张 852×438 的真实聊天截图，以及由它放大得到的 2560×1316 大图（模拟 Retina 全屏截图）。

## 5. 性能测试

### 5.1 识别耗时对比（同一张截图）

| 场景 | 耗时 | 说明 |
| --- | --- | --- |
| 优化前（OpenAI 兼容接口，冷启动，无参数调优） | 44.1 s | 且返回空 JSON，属于无效等待 |
| Ollama 原生接口 + 参数调优（暖机、小图） | 14.6 s | 结果正确 |
| 上述但输入 2560px 大图 | 43.5 s | 图片像素量是主要成本 |
| 上述但输入压缩到 1280px | 18.7 s | 同样内容，概括质量更好 |
| 纯文本入参（无图） | 5.3 s | 说明瓶颈在视觉编码 |
| **优化后端到端（大图 → 自动压缩 → 识别 → 落库）** | **14.4 s** | 浏览器实测，含建单 |
| **优化后端到端（系统 OCR + 文本结构化）** | **7.6 s** | 当前默认路径 |

### 5.2 系统 OCR 耗时

连续 3 次对同一张截图执行 OCR：210 ms、196 ms、222 ms；通过服务接口调用为 227 ms 与 272 ms（含进程调度与文件读写）。

结论：系统 OCR 稳定在 200 ~ 300 ms 区间，比模型读图快约两个数量级，是本次提速的关键。

### 5.3 优化前后对比

| 指标 | 优化前 | 优化后 | 提升 |
| --- | --- | --- | --- |
| 单条工单识别耗时 | 44.1 s | 7.6 s | 约 5.8 倍 |
| 发送给模型的图片体积 | 652 KB（2560px PNG） | 80 KB（1280px JPEG） | 约 8 倍 |
| 首次识别（模型冷启动） | 每次约 30 s 加载 | 发热点预热，常驻 30 分钟 | 避免重复加载 |

## 8. 缺陷记录与修复

| 编号 | 缺陷 | 影响 | 处理 |
| --- | --- | --- | --- |
| B-01 | 本地识别偶发返回空 JSON `{}` | 工单字段全为待补充，白等 40 秒 | 改走 Ollama 原生接口并读取 thinking 字段，已修复 |
| B-02 | 思考模式与超长上下文拖慢识别 | 单条 44 秒 | 关闭思考、限制 num_ctx 与 num_predict，已修复 |
| B-03 | 大尺寸截图直接送模型 | 2560px 图耗时 43.5 秒 | 发送前压缩到 1280px JPEG，已修复 |
| B-04 | 模型闲置后被卸载 | 每次首识别多等约 30 秒 | 增加 keep_alive 与 `/api/warmup` 预热，已修复 |
| B-05 | `hidden` 属性被组件 display 规则覆盖 | 空状态、保存条可能异常显示 | 增加 `[hidden]` 全局优先规则，已修复 |
| B-06 | 列表容器列宽异常，退化为单列 | 大屏利用率低 | 显式约束列表容器列，恢复三列网格，已修复 |
| B-07 | 夜间模式主按钮浅蓝配白字 | 对比度约 2:1，不达标 | 按钮底色单独取深蓝，实测 5.42:1，已修复 |
| B-08 | 字段标签对比度 4.27:1，略低于 AA | 小字号阅读吃力 | 标签改用次级文本色，实测约 7.9:1，已修复 |

## 9. 未覆盖项与风险

1. 未做多厂商云端接口的真机联调（除智谱与本地 Ollama 外，其余厂商仅验证配置链路）。
2. 未做大并发与数据量压力测试（当前为单用户工具，数据量在十位数）。
3. 未覆盖 Windows / Linux：系统 OCR 依赖 macOS Vision。
4. 导出已验证内容与行数正确，但未校验 Excel 的公式与样式（当前导出为 HTML 表格格式的 .xls，样式能力有限）。
5. 前端搜索筛选为内存过滤，数据量上千后需要下沉到 SQLite。

## 10. 测试结论

本轮共执行 15 项功能用例、11 项界面用例、7 组性能对比，全部通过。发现的 8 个缺陷已全部修复并回归验证。

关键结论：

- 单条工单识别耗时从 44.1 秒降至 7.6 秒，达到"可用"体感。
- 识别失败不再丢失输入与截图，且有兜底建单路径。
- 双主题对比度全部满足 WCAG AA。
- 用户既有数据在全部测试过程中保持完整。

剩余风险主要集中在本机以外的环境适配与规模化场景，不影响当前个人使用。
